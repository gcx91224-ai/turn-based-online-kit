# 01 · 先选架构：三种联机模型

做联机小游戏，第一个决定不是"用什么框架"，而是**谁说了算**。选错了，后面每一行代码都在跟架构打架。

---

## 三种模型

### A. 权威服务器（服务器存状态、算结果）

```
玩家 A ──"我出石头"──▶ 服务器 ──"A 出了石头"──▶ 玩家 B
                        │
                        └─ 自己算：谁赢、扣多少血、该谁了
```

客户端只发**意图**，服务器维护真状态并广播。客户端是显示器。

- ✅ 防作弊最彻底：改前端没用，服务器不认
- ✅ 客户端可以很薄，甚至换个前端也能接同一个服务端
- ❌ 每次操作一个来回，延迟敏感的游戏会"手粘"
- ❌ 服务器要知道全部规则 —— 规则改动 = 服务端改动

**这个套件默认用这个。**

### B. 确定性锁步（只传操作，两端各跑一遍）

```
玩家 A ──"出石头"──▶ 服务器 ──转发──▶ 玩家 B
玩家 B ──"出剪刀"──▶ 服务器 ──转发──▶ 玩家 A
                        两端各自用同一份引擎 + 同一串操作，算出同一个结果
```

服务器**不懂规则**，只负责收集、排序、转发。

- ✅ 服务器极薄，规则再复杂也不用改服务端
- ✅ 带宽小（传操作不传状态）
- ❌ **引擎必须零随机、零时间依赖**，否则两端分叉，而且这种 bug 极难查
- ❌ 必须保证两端操作顺序一致
- ❌ 反作弊靠"操作合法性"，不是靠服务器算

适合：回合制、棋类、卡牌、模拟类。**不适合**任何有物理、浮点、随机数的实时游戏。

### C. 纯 P2P（WebRTC）

- ✅ 服务器只做握手，流量不过服务器
- ❌ NAT 穿透要 STUN/TURN，TURN 一样要服务器和带宽
- ❌ 作弊者可以改自己的客户端，没有裁判
- ❌ 掉线/重连/房间管理全得自己做

朋友之间随便玩玩可以，想公开让人玩就别选。

## 怎么选：一张表

| 你的游戏 | 建议 |
|---|---|
| 回合制、两人、规则简单（猜拳、井字棋、你画我猜） | **A 权威服务器** ← 本套件 |
| 回合制、规则复杂（卡牌、战棋、有隐藏信息） | A 或 B，看你想不想让服务器懂规则 |
| 实时动作、平台跳跃、需要 60fps 同步 | A + 客户端预测 + 插值（本套件不覆盖） |
| 完全信任朋友、只想省服务器 | C，但要知道代价 |
| 单机为主、偶尔联机 | 先做单机，联机当附加功能 |

> 一个常见误判：以为"服务器算结果"很麻烦。对回合制来说，服务端算一次结算的成本约等于零，
> 而它省掉的防作弊、状态一致性、断线恢复工作量大得多。

## 为什么用 Cloudflare Workers + Durable Objects

做朋友局小游戏，最痛的不是写代码，是**运维一台服务器**：进程挂了、内存涨了、被打了、证书过期了。

Durable Object 的模型刚好对上"房间"：

| 需求 | DO 给的 |
|---|---|
| 一个房间一份状态 | 一个房间码 = 一个 DO 实例，天然隔离 |
| 房间内消息有序 | 同一个 DO 的请求是**串行**处理的，不用自己加锁 |
| WebSocket | 原生支持，还能"休眠"（Hibernation）省内存 |
| 持久化 | 每个 DO 自带一小块 SQLite，`storage.put/get` 就行 |
| 不用运维 | 按请求计费，没有常驻进程要养 |
| 免费 | 免费额度对朋友局绰绰有余（见 [06-deploy](06-deploy.md) 的算账） |

代价：

- 厂商绑定（迁走要重写房间层，但也就几百行）
- 本地开发体验一般（`wrangler dev` 依赖 workerd，有些机器跑不起来 → 见 [08-testing](08-testing.md)）
- 单个 DO 是单点的：同一个房间的所有消息都排在一个实例上，热门大房间会成为瓶颈（朋友局不会）

## 本套件的结构

```
浏览器 A ─┐
          ├─ WebSocket ─▶ Worker ─▶ Room DO「房间码 AB3CD」
浏览器 B ─┘                 │
                            └─ 静态文件（public/，免费直出）
```

- **Worker**：路由。静态文件直出、`/api/room` 建房、`/ws` 转给对应房间的 DO
- **Room DO**：座位、回合、超时、重连、结算
- **浏览器**：连接、渲染、把点击变成消息。**不做任何规则判定**

只有三个文件是"你的游戏"：`worker/game.js`（规则）、`worker/room.js`（流程）、
`public/app.js`（界面）。其余都是通用管道。
